# Display engine

The card has a display engine next to the VGA core. While it is enabled, it decides what appears on screen: a packed-pixel frame in video memory at 8, 15, 16 or 32 bits per pixel. While it is disabled, the card is a plain VGA.

## Register access

The engine's registers sit in the VGA sequencer's index space, at indices 80h-BFh: write the index to 3C4h, then read or write the data at 3C5h. This makes them reachable from real-mode code (the VBE BIOS and DOS programs), and Windows' VGA virtualization (VDD) treats them like any other sequencer register: a DOS window's accesses go to its virtual copy, never to the hardware.

The registers are locked at reset. Writing 98h to SR80h unlocks them; writing anything else locks them again. While locked, SR81h-BFh read 00h and ignore writes.

Multi-byte values are little-endian across consecutive indices: the lowest index holds bits 0-7. A value takes effect as each byte is written, except START, which takes effect when its high byte (9Bh) is written; software writes the whole mode before setting the enable bit.

The 64 KB register window in BAR0 holds the GPU's registers ([gpu-registers.md](gpu-registers.md)); REGS_BASE gives its address. The GPU's FLIP packet loads START at vertical blank, as a write of START would.

## Registers

| Index | Name | Access | Contents |
|---|---|---|---|
| 80h | KEY | R/W | Write 98h to unlock, anything else to lock. Reads 01h unlocked, 00h locked. |
| 81h | ID | R | 98h |
| 82h | REVISION | R | 03h: double scan, REGS_BASE and GPU_RESET (revision 02h had no GPU_RESET; 01h had none of the three) |
| 83h | | | Reserved, reads 00h |
| 84h | FEATURES | R | bit 0 display engine, bit 1 linear framebuffer, bit 2 banked window, bit 3 EDID port, bit 4 REGS_BASE. Reads 1Fh. |
| 85h | FORMATS | R | Supported pixel formats: bit 0 8 bpp, bit 1 15 bpp, bit 2 16 bpp, bit 3 32 bpp. Reads 0Fh. |
| 86h-87h | MAX_WIDTH | R | Largest width in pixels: 1920 (the largest height is 1440) |
| 88h-8Bh | VRAM_SIZE | R | Video memory in bytes |
| 8Ch-8Fh | LFB_BASE | R | Physical address of the linear framebuffer (BAR1), or 0 while BAR1 is unassigned |
| 90h | CONTROL | R/W | bit 0 ENABLE: the engine drives the display. Bit 1 DSCAN: double scan, every pixel and line shown twice (below). Other bits reserved (write 0). |
| 91h | FORMAT | R/W | Bits per pixel: 8, 15, 16 or 32. Other values are ignored (the register keeps its value). |
| 92h-93h | WIDTH | R/W | Visible width in pixels, 8-1920 (rounded down to a multiple of 8; larger values act as 1920) |
| 94h-95h | HEIGHT | R/W | Visible height in lines, 1-1440 (larger values act as 1440) |
| 96h-97h | PITCH | R/W | Bytes from one line to the next, rounded down to a multiple of 4. 0 means width × bytes per pixel. |
| 98h-9Bh | START | R/W | Byte offset in video memory of the first visible pixel, rounded down to a multiple of 4. The engine takes a new value when 9Bh is written (and when ENABLE is set), and shows it from the next frame: it is latched as vertical retrace begins. |
| 9Ch | REFRESH | R/W | Frame rate in Hz, 50-160; any other value means 60. Paces the emulated vertical retrace. |
| 9Dh | | | Reserved |
| 9Eh-9Fh | BANK | R/W | 64 KB bank shown in the A0000h window in extended mode |
| A0h | EDID_INDEX | R/W | Byte index into the monitor's EDID block, 0-127 |
| A1h | EDID_DATA | R | The EDID byte at EDID_INDEX; the index then advances (modulo 128) |
| A2h-A3h | SCRATCH | R/W | Storage for the VGA BIOS, no effect on the display. The VBE BIOS keeps the current VBE mode number and its flags here ([bios.md](bios.md)). |
| A4h-A7h | REGS_BASE | R | Physical address of the register window (BAR0), or 0 while BAR0 is unassigned |
| A8h | GPU_RESET | W | Writing 01h puts the GPU in its power-on state ([gpu-registers.md](gpu-registers.md)): ring, holds, FENCE, the status block and the SYSBUF registers. The VGA BIOS writes it at POST; reads 00h |
| A9h-BFh | | | Reserved, read 00h |

SR E0h is still the developer debug register ([registers.md](registers.md)).

## Extended mode

With ENABLE set:

- The screen shows HEIGHT lines of WIDTH pixels, read from video memory starting at START, each line PITCH bytes after the previous one. Addresses wrap at the end of video memory.
- Pixel formats: 8 bpp indexes the VGA DAC (6 bits per component, as in mode 13h); 15 bpp is 5-5-5 and 16 bpp 5-6-5 (red in the top bits); 32 bpp is 8-8-8 with the top byte unused (blue in the lowest byte).
- With DSCAN set, each pixel is shown twice across and each line twice down: the output is twice WIDTH by twice HEIGHT, paced as a mode of that size (so 320×240 fills a 640×480 screen, as low-resolution modes did on period cards). Video memory holds the frame at its own size.
- The frame is paced at REFRESH Hz. Blanking is generated by the engine; the CRTC timing registers have no effect, but the input status register (3BAh/3DAh) still reports vertical retrace.
- The A0000h-AFFFFh window shows 64 KB of video memory starting at BANK × 64 KB, as plain bytes (no planes, no latches). B0000h-BFFFFh is not decoded.
- The VGA registers stay readable and writable, and mostly have no effect on the display until ENABLE is cleared, when the VGA core takes over with whatever they hold. The CRTC timing and start address registers and SR01 bit 3 (half dot clock) are ignored. What still applies: SR01 bit 5 (screen off) blanks the display; the DAC's PEL mask applies at 8 bpp; and the line counting still reads CR08 (preset row scan) and CR17 bit 2, so software leaves them as mode 13h sets them (both 0), which the VBE BIOS does.

- The hardware cursor (interface 3.4) and then the gamma table (interface 3.5, the direct-colour formats alone) are applied to the frame at scan-out, never in video memory ([gpu-registers.md](gpu-registers.md)).

With ENABLE clear, the card is a plain VGA, and the other engine registers are ignored.

## Mode changes

The engine's registers are written a byte at a time, whenever software likes, so a change usually lands in the middle of a frame. In 86Box the card handles its own changes so that each transition's frames stay clean:

- **The frame a change strands is ended.** After a display engine register write that recalculates the timings (a mode change, ENABLE set or cleared, while the engine was or is on) and after a card reset: when 86Box's line counter is past the new picture's end while still in its picture, or past the new frame's total, the counter goes to the new picture's last line, out of the picture, with no rows of the frame drawn. 86Box's next vertical sync then shows no frame (the screen keeps the last one and its size), and the frame after it is the new mode's, whole. The cut frame costs about one blanking period. Without this, a counter past a shorter mode's total ran on to 2047 and wrapped, giving one frame of about 2,000 lines, which 86Box's window showed squeezed. The rule is `vgpu98_dd_end_frame` in `card/vid_vgpu98_dispdiag.h`, beside a model of 86Box's vertical counting, both checked by the host test `display_diagnostics`. A normal frame is never ended (in its picture it is always before its end, in its blanking before its total), nor one after a VGA register write: the VGA BIOS's own write of CONTROL at a VGA mode set, with the engine off, leaves the VGA's frame to 86Box.
- **A new mode's first frame is its own picture or black.** While the host GPU composes the display, a finished picture goes into 86Box's frame buffer only when it is of the mode now shown (width, height, depth, pitch, double scan, and its place). A picture of the old mode is held back, and the new mode's area is cleared to black; so is it when the host's display starts or restarts. START moving (a flip) and the palette are not a new mode.
- **VGA-to-VGA changes** are left to 86Box's VGA core, as for every card.

With Diagnostics "Display", each transition is logged and its frames captured ([registers.md](registers.md), Diagnostics).

The linear framebuffer (BAR1) shows video memory in both cases.

## Reset and VGA mode sets

A machine reset clears every engine register and locks them. A FORMAT of 0 (the reset value) acts as 8 bpp. The VGA BIOS clears ENABLE whenever it sets a VGA mode (INT 10h AH=00h, or VBE function 02h with a VGA mode number), so DOS programs that return to text mode always get a VGA display.

## Monitor (EDID)

The card describes a virtual monitor through a 128-byte EDID 1.3 block, generated from the card definition by `cardc` and readable at SR A0h/A1h. The BIOS returns it through VBE/DDC (INT 10h AX=4F15h). Its range limits and timings cover every mode in the mode table ([modes.md](modes.md)).
